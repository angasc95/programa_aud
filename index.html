Role: anon (Unauthenticated Key)
Mecanismo de Doble Capa en PostgreSQL / Supabase:

1. Capa DCL (GRANTs): PostgreSQL comprueba primero si el rol (authenticated o anon) tiene privilegios base de tabla (GRANT SELECT ON ALL TABLES...). Si falta este permiso, responde con 42501 permission denied for table organizacion antes de evaluar RLS.
2. Capa RLS (Políticas de Fila): Una vez otorgado el permiso base, las políticas en rls.sql filtran los registros visibles permitiendo acceso completo a usuarios con estado APPROVED (is_approved_user()).

Supabase SQL Scripts & DCL Fixes Hub

Instrucción: Copia y ejecuta este bloque en el SQL Editor de Supabase. Otorga privilegios a authenticated y anon para resolver el error 42501 permission denied for table organizacion: 

-- ============================================================================
-- FIX: PRIVILEGIOS BASE DE POSTGRESQL (DCL) PARA ROLES DE SUPABASE
-- ============================================================================
GRANT USAGE ON SCHEMA public TO anon, authenticated;

-- Otorgar permisos sobre todas las tablas actuales
GRANT ALL ON ALL TABLES IN SCHEMA public TO authenticated;
GRANT ALL ON ALL SEQUENCES IN SCHEMA public TO authenticated;
GRANT ALL ON ALL ROUTINES IN SCHEMA public TO authenticated;

-- Permisos de lectura pública para anon (restringido luego por RLS)
GRANT SELECT ON ALL TABLES IN SCHEMA public TO anon;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO anon;
GRANT EXECUTE ON ALL ROUTINES IN SCHEMA public TO anon;

-- Configurar privilegios automáticos por defecto para tablas futuras
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON TABLES TO authenticated;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO anon;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON SEQUENCES TO anon, authenticated;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT ALL ON ROUTINES TO anon, authenticated;
